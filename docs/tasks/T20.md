- **Scope**:
  - **Protects:** rule 18 (no line of decompiled code in the repository, the PR or a comment; describe
    in our own words, cite script number, name and handler); the rule that a static reading is a
    reading (every claim says it is read from code, with a confidence, and none is stated as observed
    behaviour of the running game); rule 19 (Pro only, set `iwp-2.0-996e86c5`, unregistered).
  - **F011** (proposed), template headings, for each of the 17 questions:
    - **the answer as read**, in our words: the rule, its numbers (dice sides, number of dice, how ties
      fall, losses per exchange, minimum armies to attack, what a failed attack costs, the move-in after
      a capture, how many moves per turn, whether an attack repeats);
    - **its sources**: script number and name, handler, and the binary's sha256 (`static:decompile`);
    - **its confidence** (rule 22), and what would change it;
    - **its corroboration plan for T28**: what to count in recorded play, and how many cases, or
      `static-only` with why;
    - where the human's and the computer's code paths differ (for example `RollDice` against
      `ComputerRollDice`), both, and whether they give the same rule.
  - **Randomness:** say where a random number is drawn and how it is used; the generator itself is in
    Director's runtime (T18), so its distribution is not claimed.
  - **"What this does not establish"**: at least the runtime faithfulness of the decompiler, the
    registered build, and anything gated by `UPG`.
  - **Not in scope:** reinforcement (T21), cards (T22), centres and hazards (T23), the AI's choices
    (T27), turn order and victory (T30); any run of the game.

  - **Stating a reading as the running game's behaviour**: T28 corroborates.

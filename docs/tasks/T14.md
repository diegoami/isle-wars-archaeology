# T14 Observable-state inventory: DOS Isle Wars (W4b)

- **Kind**: research (an inventory finding, with exploration runs; no driver)
- **Issue**: #52 · **Branch**: `task/T14-iw-dos-state-inventory` · **Merge after**: T11 (merged)
- **Implementer**: claude sonnet (`task-agent`, high), worktree isolation, on the user's machine
  (C3; OpenCode cannot reach the copy, L26). It is research on the user's install (rule 6). The
  seal itself is not changed here, only reused, so the "Opus for seal work" exception does not
  apply. Escalation applies (rule 6): Sonnet → Opus. A savestate or memory question Sonnet cannot
  explain is a tripwire: hand back, never guess a format.
- **Reviewer**: opencode `gpt-6.1-sol` (GPT-6.1 Sol, effort `low`), another family. Substitutes:
  GLM-5.3, then DeepSeek V4 Pro. A Claude reviewer is never allowed. Lines marked `[C3]` need the
  copy or the display, so the main session runs them and posts their output on the PR.
- **Hard** (rule 6): it adds navigation past the option box across several files of T11's cycle,
  and every new launch must keep T11's seal.
- **Why**: lane `b` needs to know where DOS Isle Wars' state can be seen, how cheaply, and at what
  intervention level, before its driver (W5b) and experiments. DOS may offer more than Pro does:
  the option box has "Load saved game" (F005), so the game probably saves. DOSBox-X savestates hold
  the emulated memory (I2 and I1, F005).
- **Evidence**:
  - game-archaeologist 07, W4a and W4b: "observable-state inventory per artifact: each source
    classified directly-observable / parsed / inferred / invasive, cheapest first; in-artifact help
    text transcribed into W2's map as `documented`". Its review test: "reviewer re-derives one
    'parsed' source's change from two saves".
  - `vocabulary/interventions.md` (at the pin), levels:
    - `I0`, pure observation, which includes parsing a file the game wrote;
    - `I1`, passive instrumentation: screenshots, read-only memory, static analysis;
    - `I2`, a modification claimed neutral, which includes a savestate;
    - `I3`, behaviour-altering, such as a crafted save or a memory write.
  - F005 (T11): the run directory and seal, the cycle, mouse-only input through xdotool, the option
    box (Set level / Default / Load saved game) as the known screen, about 13–17 s to it, and
    identical screens across 15 runs. `ISLEWAR.SCR` (20 bytes) is written at every launch;
    `ISLEWAR.DFT` (9 bytes) after Default, seen in exploration. The savestate is a zip whose Memory
    member inflates to about 17 MB; the build has no debugger. **Not reached:** a level, Default,
    Load saved game, the board, a turn, Sound, Scores.
  - F004 (T10): the 17-file set `iw-dos-3.1-30121376`. `ISLEWAR.DAT` is comma-separated decimal
    text. `ISLEWAR.DOC` is the shipped manual, readable in the copy.
  - F003 (T09), Pro's inventory: the shape to follow, its table and its two-run rule.
  - The research questions (`questions/malpaco.md`, T07). Q-SET-05 asks whether the game saves,
    and what a save holds. The P1 groups need, at least: owner and armies per territory, whose
    turn it is, the phase, dice and outcomes, cards, hazards and production centres, and the end
    of the game.

- **Scope**:
  - **Protects:** T11's seal on every launch:
    - the run copy verified with `check --strict` immediately before launch;
    - only the run copy mounted, as `C:`;
    - `IW_DOS_DIR` bound read-only, with no alias of it in the run directory;
    - DOSBox-X in its own network namespace;
    - `completed` only on a clean finish.

    It also protects the inventory's two-run rule: no field meaning without two runs that change in
    line with a stated action.
  - **Reach the screens.** Record runs that reach, and screenshot, each of these, cheapest path
    first:
    - the option box;
    - Set level, with every choice;
    - Default;
    - Load saved game;
    - the setup;
    - the board at the start of a game;
    - one human turn: one placement or move, and one attack with its result;
    - an AI turn;
    - Help or the in-game text;
    - Scores;
    - Sound;
    - any save path.

    Where a screen cannot be reached, record `not reached: <why>`. Never press a key or click that
    would order, register or reach a network.
  - **The sources.** For every source found, record:
    - what state it shows;
    - its class: `directly-observable`, `parsed`, `inferred` or `invasive`;
    - its intervention level and its cost (seconds, and the runs it needs);
    - the runs that show it.

    Order the table cheapest first. Candidates to test:
    - screen regions;
    - the files the game writes (`ISLEWAR.SCR`, `ISLEWAR.DFT`, any save file);
    - `ISLEWAR.DAT`, read only as shipped bytes;
    - the savestate's members (I2), classified;
    - the emulated memory read from a savestate (I1 over an I2 capture), classified only.
  - **Parsed sources.** For each one, give its format as far as observed: byte offsets, fields and
    encodings. Each field's meaning must be shown by at least two runs whose values change in line
    with a known action, for example `ISLEWAR.DFT` after Default at two different levels. Each
    becomes a proposed representation row in F007 (ID, representation, scope `DOS`, basis, runs).
  - **Saves** (Q-SET-05): does the game save and load? Under what name? Does a save change when the
    board changes (two saves after a known move)? Record the answer, even if it is no.
  - **In-game text:** where the game shows text that `ISLEWAR.DOC` does not have, add it to the
    knowledge map as `documented` (DOS). Use short quotes of a line at most, each citing its bundle
    and run.
  - **F007** (proposed), from `formats/templates/finding.md`, in F003's shape:
    - Artifact `iw-dos-3.1-30121376` (or its successor where a run writes); Experiment E005; tier V2;
      the maximum intervention as observed;
    - the source table, the proposed representation rows and the screens reached;
    - a comparison column with F003, where the same state exists in Pro: scope each claim to DOS
      only (rule 19);
    - "What this does not establish".
  - **Not in scope:**
    - any game rule;
    - unpacking PKLITE or decompiling;
    - finding game state in memory beyond classifying the memory source (that is W5b and later);
    - crafted or edited saves or memory (I3);
    - the W5b driver.

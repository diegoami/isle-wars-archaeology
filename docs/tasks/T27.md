  This task reads the choosing itself — how it scores candidate countries, when it attacks, when it
  moves, and what its difficulty changes — which is the behaviour malpaco's own AI will be measured
  against. This is the area where runs would show least and the code shows most.

- **Scope**:
  - **Protects:** rule 18 (no line of decompiled code in the repository, the PR or a comment; describe
    in our own words, cite script number, name and handler); a static reading is a reading (every claim
    says it is read from code, with a confidence, and none is stated as observed behaviour of the
    running game); rule 19 (Pro only, set `iwp-2.0-996e86c5`, unregistered).
  - **F016** (proposed), template headings as F011's to F013's, for each of the 5 questions:
    - the answer as read, in our words, with its numbers: how the computer picks placement countries
      (the candidate scoring, the island-completion priorities, the VIPC list's weights, the
      production-centre cases, the one-at-a-time versus split branches and their draws), when and
      wherefrom it decides to attack (the gates F011 found are the frame; this task reads the
      choice of target and timing), when and how it moves after attacks, how its card play uses the
      fixed priority F013/F014 found, and what the difficulty setting changes in any of it;
    - its sources: script number and name, handler, and the binary's sha256 (`static:decompile`);
    - its confidence (rule 22), and what would change it;
    - its corroboration plan for T28 (what to count in recorded play), or `static-only` with why;
    - where the difficulty levels differ, per level as far as the code separates them.
  - Tables a later task can use, in our own words: the computer's turn, step by step (what it
    decides, from what inputs, with what draws), and the difficulty table (level, what it changes).
  - **"What this does not establish"**: at least the decompiler's runtime faithfulness, the undecoded
    score (frame order), the registered build, anything gated by `UPG`, the *quality* of the play
    (a reading says what the code does, not whether it plays well — that is T28's and malpaco's to
    measure), and the played frequencies of its drawn choices.
  - **Not in scope:** the shared rules the computer obeys (income, placement mechanics, cards,
    combat dice, turn order — F011 to F014), the human's paths; any run.

- **Hazards**:
  - **Quoting code** to make a point (rule 18).
  - **A rule from a name**: read the body; the 903-line handler must be read in full, in order, with
    its draws and branches; do not infer the middle from the head and tail.
  - **One number where the code draws**: a draw range is not a fixed value; say the range and the
    draw.
  - **Stating a reading as the running game's behaviour**: T28 corroborates.
  - **Harmonizing with F011/F013**: if this reading disagrees with what they skimmed, say so; a
    contradiction is a finding, not something to smooth over.

# T36 check_no_originals.py constraint F: gate wine-on-user-machine runs on F019 hash

- **Kind**: infrastructure (companion change to the rule 18 carve-out, CLAUDE.md 2026-10-08, commit 9cbf505)
- **Issue**: #108 · **Branch**: `task/T36-check-no-originals-wine-gate` · **Merge after**: T35
- **Implementer**: opencode `deepseek-flash` (DeepSeek V4.1 Flash on the OpenCode Go route, effort
  `high`), rule 6's hard pair, after the quota check. Fallback: Sonnet — the implementer moves up
  one step on the next round if the review asks for rework with three or more blocking findings
  (rule 6, the escalation-after-a-heavy-review step).
- **Reviewer**: opencode `gpt-6.1-sol` (GPT-6.1 Sol on the direct OpenAI route, effort `low` —
  sparingly, per the owner note: "medium only when the task file says why"; this check does not
  need medium), another family, after the quota check. Substitutes: Luna (an easy reviewer

- **Hard** (rule 6): a guard, a gate, or a tool whose failure would let an original or a copy
  through. The check is the load-bearing piece of the carve-out: if it does not fire, a model
  could `wine /mnt/c/.../Islepro.exe` and write a run record that CI accepts. The implementer
  is the named hard pair; the reviewer is Sol at effort `low` because the contract is narrow
  (a single decision per record), not because the work is easy.

- **Why**: The rule 18 carve-out (CLAUDE.md, 2026-10-08) permits a model agent to run the
  original Pro binary under Wine on the user's machine, but the carve-out is only operational
  when `tools/check_no_originals.py` enforces constraint F. T35 produces the F019 hash table
  the gate reads. T37 produces the task file the gate's first run will be dispatched under.
  Without the gate, neither the carve-out nor the carve-out's "corroboration, not replacement"
  framing can hold: a malicious or careless run record could claim `runtime.platform =
  wine-on-user-machine` and pass CI on the strength of the platform name alone.
- **Evidence**:
  - CLAUDE.md rule 18 carve-out, constraint F: the contract this check implements.
  - `findings/F019-pro-setup-rules.md` "Known-good binary hashes" (T35): the table the gate
    reads.
  - `tools/check_no_originals.py`: the existing case-insensitive `*.[eE][xX][eE]` bar and
    every other check the script runs, so the new check is additive and does not duplicate
    existing work.
  - `formats/run-1.schema.json`: the `runtime.platform`, `start_state.sha256`,
    `artifact.set`, and `artifact.variant` fields the gate reads.
  - `formats/evidence-manifest-1.schema.json`: the evidence-class enum, so the gate can also
    require evidence with class `recording` for wine-on-user-machine records (constraint C
    of the carve-out).
- **Owns**:
  - `tools/check_no_originals.py` (modified): a new check function `check_wine_gate(record,
    f019_table)` that returns `("", "")` on pass and `("[E0XX] wine-on-user-machine record
    whose start_state.sha256 is not in the F019 table", "")` on refusal.
  - `tools/tests/test_check_no_originals.py` (new or modified): mutation tests covering at
    least the cases in the Done-when list.
  - `tools/check_no_originals.py` CLI: the check is run by default, with `--no-wine-gate`
    available for the local-dev case (and CI never sets that flag).
- **Scope**:
  - **Protects:** rule 18 (the original's bytes do not enter the repo, a release, an issue,
    or a cloud session, and a run record whose `runtime.platform = wine-on-user-machine`
    without a matching F019 hash is refused); rule 20 (the check does not mutate the record
    it inspects); rule 7 (CI is green before merge).
  - The check refuses a record whose `runtime.platform` starts with `wine-on-user-machine`
    and whose `start_state.sha256` is not in the F019 table.
  - The check refuses a record whose `runtime.platform` starts with `wine-on-user-machine`
    and whose `start_state.sha256` matches an F019 row, but the row's set+variant does not
    match the record's `artifact.set` and `artifact.variant`. (The F019 row is the
    set+variant-keyed known-good; a mismatched set+variant is a misconfigured run.)
  - The check refuses a record whose `runtime.platform` starts with `wine-on-user-machine`
    and whose `start_state.sha256` is the all-zero placeholder
    `0000…0000` (the value T28 used for "no save file") — the owner-plays path is not
    accidentally allowed.
  - The check passes a record whose `runtime.platform` is something other than
    `wine-on-user-machine`, regardless of `start_state.sha256` (the existing checks do
    the rest).
  - The check is implemented as a single decision per record, runs in O(1) over the F019
    table (the table has one row, possibly a handful in the future), and produces a
    refusal message that names the row it expected and the row it got.
  - **What this does not establish:** the check does not verify the binary's *behaviour* —
    a hash match says the named binary is the F019-known one, not that the run is correct.
    That is T37's job, and the per-claim finding's job, not the gate's.
  - **Not in scope:** the F019 table (T35), the T-number task file (T37), the harness copies,
    any watcher or click-driver code, any run of the original.
- **Done when**:
  1. `tools/check_no_originals.py` has the new check function and the CLI runs it by default.
  2. The mutation tests cover: removing the F019-row match (the check still passes, because
     the platform is not wine-on-user-machine); flipping the platform prefix to
     `Wine-On-User-Machine` (the chosen case-sensitivity contract is named in a docstring or
     test name); flipping the F019 table to an empty list (every wine run refused); the
     set+variant mismatch case; the all-zero placeholder case.
  3. A test record with `runtime.platform = wine-on-user-machine` and
     `start_state.sha256 = c4d7a248…594e` (the T35 row's hash) and
     `artifact.set = iwp-2.0-996e86c5` and `artifact.variant = unregistered` passes the
     check.
  4. A test record with `runtime.platform = wine-on-user-machine` and
     `start_state.sha256 = 0000…0000` is refused with a message that names the placeholder.
  5. `python3 tools/check_no_originals.py` exits 0 on `main`; the new tests run under
     `python3 -m pytest tools/tests/test_check_no_originals.py` and pass.
  6. CI is green; the PR has an approving review from the named Sol reviewer.
- **Hazards**:
  - **A platform-name spelling drift** (`wine-on-user-machine` vs `WineOnUserMachine` vs
    `wine-on-user-machine-iwp-2.0`): the check's contract is "starts with
    `wine-on-user-machine`", and the test names the chosen case-sensitivity. If the
    contract is case-sensitive, a single capitalisation change in a future task file lets
    a model bypass the gate; the test catches that.
  - **The all-zero placeholder**: T28 used `0000…0000` for "no save file." A check that
    treats that as a valid hash is wrong by rule 18's spirit; the test pins the refusal.
  - **The F019 table being empty** at the moment T36 lands: the gate refuses every
    wine-on-user-machine record until T35 lands, which is the right behaviour. The order
    matters: T35 must be merged first. The merge-after list reflects this.
  - **A check that does more than it says**: the gate's only job is the F019 hash match.
    Do not add behaviour checks, do not add a "did the watcher run on the user's machine"
    probe, do not add a sandbox check. Those are T37's job.

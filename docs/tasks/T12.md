- **Hard** (rule 6): `register_artifact.py check` is part of both seals. `setup/iwp/prefix.py`
  imports its `hash_tree` and `compare` to verify the game copy before every Pro launch, and
  `setup/iw-dos/rundir.py` runs `check --strict` before every DOS launch. A tool swap that weakens
  either check would let a changed or wrong copy through. The task also changes several files
  and adds an external dependency (the pinned upstream code).
- **Why**: game-archaeologist ADR-009 moved both tools upstream once several repositories carried
  copies, and the copies here have drifted. `tests/formats/check_examples.py` already differs
  from upstream below `def validate` (#42).

- **Scope**:
  - **Protects:** both seals' copy checks (the Pro prefix's game copy, and the DOS run copy with
    `check --strict`) and the validity of every committed record. After the swap, each must refuse
    at least everything it refused before.
  - **Pin** `archaeology.json` at `69566be`. List `tools/validate_records.py` and
    `tools/register_artifact.py` in `uses`. Bring the two tools and `formats/*.schema.json` in
    byte-identical to that commit, each in `vendored` with its sha256, and drop
    `tests/formats/check_examples.py` once nothing calls it. A test fails when any vendored file's
    bytes differ from its pinned hash.
  - **Validator (#42):** replace every use of the vendored `check_examples.py` with the pinned
    validator (its CLI or `validate_document`). `tests/test_runs.py` validates every record under
    `runs/**` and every manifest under `evidence/**` with it.
  - **register_artifact.py (#48):** replace the local tool with the upstream one, and adapt every
    caller to its API. `prefix.py`'s in-process use must keep the same comparison: every listed file
    present with its bytes and sha256, nothing unlisted, and a special file or an escaping link a
    failure. If the upstream `hash_tree` or `compare` signature differs, adapt the caller and
    never re-implement the comparison. This repository's tool already uses the `manifest`, `check` and `validate`
    subcommands, so no command line changes form. Any flag a doc or script uses must exist
    upstream. Committed run records and measurement scripts keep the commands they recorded.
  - **Re-validate and report, never change:** run the pinned validator on every file under
    `runs/` and `evidence/`, and `register_artifact.py validate` on `artifacts/known.json`. Write
    the outputs under `experiments/T12-tool-migration/measurements/`. Any file or set that now
    fails is listed in the PR body with its error, and filed as an issue. It is never edited here.
    The stricter rules include NaN and Infinity, duplicate keys, lone surrogates (#42), paths with
    `..`, backslashes or drive letters, and `runtime_writes` leaving `files` (#48).
  - **Not in scope:** changing any schema, record, manifest or set; the `formats-v1` tag; any new
    seal behaviour.

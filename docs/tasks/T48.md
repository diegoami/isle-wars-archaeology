  - **The gate.** Constraint F also covers every record whose `runtime.platform` contains `wine`,

    - such a record passes only if its path is listed in `tools/legacy_wine_records.txt` with

- **Hazards**:
  - **Rewriting `runs/`.** Never edit, re-hash or regenerate a record to make it pass. The list
    exists so that the records stay as they are (rule 20).
  - **A list that accepts by prefix or by name alone.** The list is matched by exact path and file
    sha256. A copy of a listed record under a new name, or an edited listed record, must fail. Sol
    found exactly this kind of bypass in T36 (#9).
  - **`wine` matched case-sensitively, or as a prefix.** The legacy token has `wine` in the middle.
    `WINE` must not slip past.
  - **Hashing the wrong file.** `start_state.sha256` is the `Islepro.exe` that ran, read from the
    bound install, not the prefix, the run copy or a constant. A constant would pass CI and prove
    nothing: the test feeds two different fake binaries.
  - **The schema.** `start_state` takes no extra fields. A `prefix_sha256` key there breaks
    validation.

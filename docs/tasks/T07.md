# T07 malpaco's rules as research questions

- **Kind**: research (planning input for W6)
- **Issue**: #16 · **Branch**: `task/T07-malpaco-questions` · **Merge after**: —
- **Implementer**: claude sonnet (`task-agent`, high), worktree isolation (rule 6: research)
- **Reviewer**: opencode `luna` (GPT-6 Luna, high), another family
- **Why**: The owner decided on 2026-10-02 that this repository's findings feed malpaco, an original
  game inspired by *Isle Wars Pro*. malpaco's existing code is reclassified as a technology proof of
  concept. Its postmortem (malpaco `POSTMORTEM.md`, 2026-10-02) found two problems:
  - every rule and number was guessed, and attacking is never worth it, with a stalemate in about
    one game in six that no tuning fixed;
  - the UI is weak. The owner wants a UI at least as good as Pro's.

  This task turns malpaco's rules into questions about the originals, so that the research targets
  what the game needs.
- **Evidence**: malpaco at `2da373d` (private, read with `gh api`):
  - `RULES.md` (391 lines) and `SCENARIOS.md` (240);
  - `POSTMORTEM.md`;
  - `DECISIONS.md`, "Gorgeous, and what that costs" and "The floor was the stalemate";
  - this repository's `knowledge-map.md`, with 17 areas including "User interface".
- **Owns**: `questions/**`.
- **Scope**:
  - **`questions/malpaco.md`**: one row per rule or constant in `RULES.md` and `SCENARIOS.md`. Each
    row has:
    - an id (`Q-<AREA>-<nn>`);
    - malpaco's statement, cited as file:line at `2da373d`, quoted in one line at most;
    - the knowledge-map area;
    - the question about the originals, falsifiable, saying what observation would answer it;
    - the scope: DOS, Pro or both;
    - the likely method: observe, parse or static;
    - the priority:
      - **P1**: it bears on the stalemate (including `RULES.md`, "Games that do not end"), on
        whether attacking pays, or on the AI, which malpaco never built;
      - **P2**: other rules;
      - **P3**: cosmetic.
  - **A UI section**: each UI weakness malpaco's own documents record, cited, becomes a question
    about Pro's UI, for W4a to observe. These are V3 or V4 claims (U8).
  - **A coverage table**: every `##` and `###` heading of both files, with the ids that cover it,
    or "no question: <reason>".
  - **`questions/README.md`**: what goes in this directory, in one paragraph.
  - **Not in scope**: answering any question, or changing any knowledge-map status (every row
    stays `unknown`). No edits to malpaco.
- **Done when**:
  1. The coverage table lists exactly the headings from
     `gh api 'repos/diegoami/malpaco/contents/RULES.md?ref=2da373d' -H 'Accept: application/vnd.github.raw' | grep -E '^#{2,3} '`,
     plus the same for `SCENARIOS.md`. The reviewer regenerates the list and compares.
  2. Every row has all seven fields. Its area is one of `knowledge-map.md`'s areas. Its question
     names the observation that would answer it.
  3. The P1 rows include the stalemate, whether attacking pays, and the AI. The UI section has at
     least one question per UI weakness cited.
  4. No row asserts how an original behaves: they are questions, not claims.
  5. `python3 tools/check_links.py` and `python3 tools/check_no_originals.py` exit 0, and CI is
     green.
- **Hazards**:
  - answering a question from memory, a wiki or malpaco's own guesses;
  - scoping a question to "both" by default: say why both;
  - copying long passages of malpaco text instead of citing it.

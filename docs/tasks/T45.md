- **Scope**:
  - **The player.** A loop on E020's model (`e020_loop.py`'s structure, and its screens and New Game
    rule unchanged) that plays the human seat:
    - on each human turn, read the board (`read_board`) and pick the next needed case from the table
      below;
    - grow a stack by placing **all** reinforcements on one frontier country until it reaches the
      case's attacker size;
    - attack an adjacent enemy whose army count fits the case, and read the board after every attack
      click;
    - log each attempt (the case, the attacker and defender before and after, the clicks, the
      frames).
    - When no case fits, pass. A game ends as E020's do, and the next starts from the title only.
  - **The cases and their counts** (the playbook's Session A, the owner's choices of 2026-10-07):

    | Case | Attack | Count | Claim |
    | --- | --- | --- | --- |
    | even | attacker N in {2, 4, 8, 12} vs defender N−1, N, N+1, N+2 | 16 (one per cell) | Q-CMB-01 |
    | underdog | attacker 4, 8, 12, 20 vs a strictly stronger defender | 4 | Q-CMB-02 |
    | tiny | attacker 1, 2, 3 vs a defender of 1 | 3 | Q-CMB-03 |
    | quit | the quit-attack button mid-battle | 2 | Q-CMB-08 |
    | lost | attacks that fail; what happens to the turn | 5 | Q-CMB-09 |
    | busy | turns with 3 or more attacks; what ends each | 10 | Q-CMB-10 |

    An attacker of 1 may be refused by the game: the refusal is the observation, recorded as such.
    Stacks above 12 that are not reached in a sitting are recorded as unreached, and the outcome is
    narrowed (the owner, 2026-10-07: "small stacks 2/3/5 only, 10+ marked narrowed if unreached").
  - **The progress number** (L58). `measurements/progress-r<nn>.json` counts the cases met out of 40,
    per row and in total, across all E021 records. It is written after each sitting's export,
    committed with the records, and never overwritten (a new `r<nn>` each time, rule 20). A resumed
    batch starts from the latest one.
  - **Records**: run/1 records under `runs/E021/session-a/`, exported as E020's are, with
    `runtime.platform` `wine-on-user-machine-iwp-2.0` and `start_state.sha256` the F019
    `Islepro.exe` hash, so constraint F's gate accepts them. Evidence class `recording`. No original
    text in `observations[]` (constraint D).
  - **Not in scope**: moves and captures (Q-MOV-01/02/03, Q-OWN-01), a later task; computer-vs-computer
    exchanges (T44, T46); per-claim outcomes in a finding (T28's F021); scheduling beyond the main
    session running batches by hand (a timer can follow once a batch runs clean).
- **Done when**:

     least 1 case met.
  3. `[C3]` The first sitting's PR comment states whether one attack click gives one exchange,

  4. `python3 -m unittest discover -s tests`, `python3 -m unittest discover -s tools/tests`,

- **Hazards**:
  - **New Game mid-game credits a loss** and moves the install to the successor set (F003, F019).
    Reuse E020's title-only rule; never write your own New Game path.
  - **One click, several exchanges.** If the first sitting shows that an attack click resolves more
    than one exchange, the per-exchange cases are not single. The main session stops and decides
    with the owner (T44's capture may then be needed here too). Never work around it in code.
  - **The deal is random** (F018): a case may not appear for many games. Record what was looked for
    and not found; never force a board.
  - **Original text** (constraint D): button labels and messages are named by their role (the
    attack button, the quit-attack button), never quoted in records.
  - **The implementer cannot run the game** (L26): it writes the player and its tests, and the main
    session runs the sittings and posts their output.

# T29 Reviewer read access to the machine-local static folder

- **Kind**: harness (a local adaptation of the OpenCode reviewer's permissions; no research)
- **Issue**: #81 · **Branch**: `task/T29-reviewer-static-access` · **Merge after**: —
- **Implementer**: claude opus (`task-agent-heavy`, effort `medium`), worktree isolation. Opus, not
  the hard pair's DeepSeek V4.1 Flash, because the task changes the permissions of the OpenCode
  agents themselves (the owner, 2026-10-05).
- **Reviewer**: opencode `gpt-6.1-sol` (GPT-6.1 Sol, effort `low`), another family, after the quota
  check (rule 6). Substitutes: GLM-5.3, then DeepSeek V4 Pro. Lines marked `[C3]` need the static
  folder, so the main session runs them and posts their output on the PR.
- **Hard** (rule 6): a guard. Its failure lets an OpenCode reviewer read or write outside its
  worktree beyond what is granted, or leaves static readings unreviewable.
- **Why**: Static readings (T20–T23, T27) can only be checked against the decompiled source, which
  stays in `$IWA_STATIC` on the owner's machine (rule 18). The owner chose, on 2026-10-05, to let the
  OpenCode reviewers (OpenAI and Z.ai models) read that folder, and recorded in rule 18 that model
  APIs may read derived output. Also #78 item 5: in T16 and T26 Sol refused Done-when lines that need
  a TMPDIR outside the worktree, or mutations made in place and restored, because review.mjs's output
  rules and the agent file forbid both.
- **Evidence**:
  - `.opencode/agents/reviewer.md`: `permission.external_directory` denies `/tmp/opencode/*`;
    everything else outside the worktree is auto-rejected. Its prose says "Stay inside your worktree:
    no temp directory" and allows in-place mutations restored with `git checkout -- <file>`.
  - `tools/harness/review.mjs:186`: "Do not post to GitHub, edit, commit, push, label or merge
    anything."
  - `tools/harness/lib/opencode.mjs`: how a rejected permission is detected and reported.
  - `harness.lock`: both files are pinned copies of harness_imperial; a local change is recorded as an
    `adapt <path>  (<why>)` line, and the file's hash line is removed (see the existing adapt lines).
  - OpenCode 1.18.34 (`opencode --version`): whether `external_directory` patterns expand `~` or
    environment variables. Find out from its documentation or source; never guess.
- **Owns**: `.opencode/agents/reviewer.md`, `tools/harness/review.mjs` (the output-rules text only,
  and any code needed to pass the granted path at run time), `tools/harness/lib/opencode.mjs` only if
  the path must be templated at run time, `harness.lock`, the matching tests under `tools/harness/`
  or `tests/`, and a note in `docs/environment.md` (where the static folder is granted).
- **Scope**:
  - **Protects:** the reviewer reads, and only reads, two places outside its worktree: the static
    folder (`$IWA_STATIC`, by default `~/.local/share/isle-wars-archaeology/static/`) and a scratch
    TMPDIR matching `/tmp/iwa-review-*`. It writes only in the TMPDIR and, for a restored mutation,
    in its worktree. Every other outside path stays rejected. No machine path is tracked.
  - **The grant:** allow those two patterns in `external_directory`. If OpenCode does not expand `~`
    or a variable, the harness fills the absolute path in at run time (for example by writing the
    agent file into the run's data directory, or by OpenCode's config environment variable), so the
    tracked file holds no machine path.
  - **Writes in the static folder:** deny the edit tool there; deny the obvious shell writes to it
    (`rm`, `mv`, `cp … <static>`, output redirection into it) as far as OpenCode's bash patterns can
    say so, and state in the PR what they cannot stop.
  - **The rules text:** the agent file's "Stay inside your worktree" paragraph and review.mjs's output
    rules say what is now allowed: reading the static folder; a TMPDIR under `/tmp/iwa-review-*`,
    removed afterwards; mutations made in place, restored with `git checkout -- <file>`, never
    committed. Everything else stays forbidden.
  - **harness.lock:** an `adapt` line for each changed pinned file, with the reason.
  - **Not in scope:** the implementer agent's permissions; the Claude reviewer; upstreaming to
    harness_imperial (file a follow-up issue there, or say why not).
- **Done when**:
  1. `.opencode/agents/reviewer.md` grants read of the static folder and the `/tmp/iwa-review-*`
     TMPDIR, and nothing else new; the edit tool and the listed shell writes into the static folder
     are denied.
  2. `[C3]` The main session runs one probe with the reviewer agent on a cheap model (GPT-5.6 Luna),
     in a scratch worktree, through the same code path review.mjs uses. It must:
     - read one `.ls` file under `$IWA_STATIC` and print its sha256;
     - create, use and remove a TMPDIR under `/tmp/iwa-review-`;
     - be rejected reading a file elsewhere outside its worktree (for example under
       `~/.local/share/isle-wars-archaeology/E007-bundles/`);
     - be rejected (or blocked) deleting or writing a file in `$IWA_STATIC`.
     The PR gives the exact command.
  3. Tests run by `python3 -m unittest discover -s tests` (TMPDIR outside every checkout) fail when the
     grant is removed, when an extra outside path is granted, or when the run-time path filling (if
     any) is removed; show the mutants killed. `node tools/harness/review.mjs --self-test` still
     passes (it checks how reviews are read, not permissions). Amended on main, see the commit.
  4. `grep -E '^[0-9a-f]{64}  ' harness.lock | sha256sum -c --quiet` passes, and each changed pinned
     file has an `adapt` line.
  5. No tracked file contains a machine path: `git grep -n -E '/home/|/mnt/' -- .opencode tools/harness harness.lock`
     prints nothing new.
  6. `python3 tools/check_no_originals.py` and `python3 tools/check_links.py` exit 0, and CI is green.
- **Hazards**:
  - **A grant wider than asked** (a parent folder, `~/*`, `/tmp/*`).
  - **A machine path in a tracked file.**
  - **A reviewer that can now write or delete in the static folder** without the PR saying so.
  - **Breaking every review**: a malformed agent file stops all OpenCode reviews; the probe proves it
    still runs.

# T44 Fast capture: single computer-vs-computer exchanges from a model sitting

- **Kind**: research plus a small mechanism (a static-first probe into the Lingo, and one of three
  capture mechanisms to make exchanges that are known to be single appear in a model sitting)
- **Issue**: #142 · **Branch**: `task/T44-fast-capture` · **Merge after**: #141 (driver aborts), the
  harness bump to `harness_imperial` 610f979, and T45's merge
- **Implementer**: opencode `mimo-flash` (MiMo v2.6 Flash on Go, no variant), after the quota check
  (rule 6). **Hard**: a new mechanism across driver and reader. Per rule 26, on a hard OpenCode
  implementer is the right pair, and Sol at `low` is the owner-pinned hard reviewer. The static-first
  gate (rule 24) is the first task — the Lingo reading names the input and the state before any

- **Why**: the E020 wine-driven sittings capture a frame every 0.4–1.4 s, and the computers resolve
  several exchanges in that window. Three sittings yielded 0 single exchanges and 55 net observations
  (`experiments/E020-wine-first-run/outcomes.json`), so Q-CMB-04..07 and Q-CMB-11 stay unestablished
  however many sittings run. The owner decided on 2026-10-09 that this needs "a faster capture (a
  later task)". Since `b82e55f` (carve-out E amended), model sittings may carry T28's counts on their
  own.

- **Scope**:
  - **Static-first gate (rule 24, B):** before any of the three candidates runs, the Lingo is read
    for the option that spaces exchanges beyond the capture interval, and for the per-attack state
    the process holds. The static reading names the input it would take and what it would read.
    T44's first PR is a per-candidate static reading (F019-style) — the Lingo references, the handler
    numbers, and the IPC or registry keys that the third candidate would target.
  - **Three candidates**, static-first (rule 24); the task picks the first that works, and says why
    the earlier ones did not:
    1. **The game's slow speed setting** (cheapest). Read `xtras/Islepro.skr` (per #152's restore
       semantics): the option names, the default, the range. If `speed = slow` spaces exchanges beyond
       the capture interval, sit at `speed = slow`, run the sitting under T45's player (read-only)
       with one computer seat attacking one another as fast as its rules allow, and observe whether
       frames now separate exchanges.
    2. **A faster stage-region grab** (mid). XShm, or `xwd -root` of a stage crop — whatever drops the
       per-frame capture into the low milliseconds without losing the per-frame evidence the reader
       needs (read-only, by hash). Reuse E020's reader for the bytes that arrive.
    3. **Process-memory reads of army counts around each attack** (last). Rule 18 B allows this once
       the static reading names the state: the Lingo names which Director field the attack uses
       (handlers read in full), and the task's reader reads that field at the same instant it
       timestamps the click, so the count is paired with the click rather than a frame later. This
       is the cheapest capture but the heaviest constraint; no original-byte write, no install path
       in the diff.
  - **Not in scope:** running the accumulation sittings (T46, settled in another task), running
    T45's full Session A on top of T44's mechanism (T45 stands on its own), any per-claim outcome in
    a finding (that is T28's F021), and changing the E020 sitting shape itself (`#141` does that).
- **Done when**:
  1. **Static reading.** One prose section per candidate, with the Lingo references (script, handler,
     numbers), the IPC or registry keys the third candidate would read, and the F019 row whose
     `Islepro.exe` sha256 the static path references. No images; no decompiled Lingo in the diff.
  2. **Offline test** that fails on `main` (the capture path is absent) and passes on the branch:
     `tools/check_counts.py --accept-single` accepts an observation the new mechanism produces from a
     synthetic session, and rejects the same observation when `--accept-single` is removed. The test
     uses synthetic frames only; no original PNGs (rule 18).
  3. `[C3]` (the main session, output posted on the PR): one model sitting recorded under
     `wine-on-user-machine-iwp-2.0` for `iwp-2.0-996e86c5` produces `runs/E022/sitting/E022-r<NNN>.json`
     with at least 20 single-exchanges accepted by `tools/check_counts.py --accept-single` (not
     `net:seq`).
  4. `python3 tools/check_no_originals.py` and `python3 tools/check_links.py` pass; CI green.
- **Hazards**:
  - **Static-first gate (rule 24).** If a candidate's static reading cannot name the state, that
    candidate is dropped; do not run it. The PR's static-reading section is reviewed before the
    capture code is.
  - **Process-memory reads (rule 18 B, amended 2026-10-08).** Reads only; the install is bound
    read-only for every run (the seal at `runtime/iwp/spike/cycle.py:protect_install`); no original
    byte is written. The reader binds no install path; the PR's diff stays under `/home/…` and
    `/mnt/…` per DW4.
  - **`speed = slow` is an option, not a patch** (rule 18): no binary edit, no skr edit in the
    repo; the sitting reads the option through the driver's options cycle.
  - **The deal is random** (F018): a faster capture does not slow it. Whatever the candidate, the
    sitting records whatever the runner saw.
  - **Original text** (carve-out constraint D): button labels and messages are named by their role
    in `observations[]`, never quoted.
  - **The implementer cannot run the game** (L26): the implementer writes the chosen mechanism and
    its offline test; the main session runs the sitting and posts its output on the PR.

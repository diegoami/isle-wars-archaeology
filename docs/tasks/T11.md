- **Scope**:
  - **The run directory.** The game runs from a copy of `IW_DOS_DIR`, in a run directory outside
    every checkout (`IW_DOS_RUN`):
    - the copy is verified with `register_artifact.py check --strict` before each launch;
    - DOSBox-X mounts only that directory as `C:`;
    - the generated configuration mounts nothing else, and the cycle checks this before launch;
    - the copy itself is bound read-only in the run's mount namespace.
  - **Record each of these with evidence and exact versions:**
    - headless and unattended launch (under Xvfb, or DOSBox-X's own output): which works, and how
      long to a known screen;
    - one input that takes effect (xdotool to the window, or DOSBox-X's own key injection), shown
      by before and after screenshots;
    - observation: a window capture, or DOSBox-X's own screenshot or capture, whichever gives
      stable bytes;
    - terminate and reset;
    - the files written at runtime (a diff of the run copy);
    - audio off (`-set "mixer nosound=true"` or the equivalent);
    - speed: the cycles setting, and the time per cycle;
    - **determinism**: do three runs from the same start show identical screens? If not, what
      varies (the timer seed, the date)? Can DOSBox-X fix the clock or the cycles?
  - **Probes, each a single arm recorded as a probe:**
    - **savestate (I2):** save at the known screen, restore, and compare screenshot hashes;
    - **debugger (I1):** is this build's debugger available? Can memory be read at a known screen
      without changing the run, for example a dump compared across two identical starts? Classify
      it only. Find no game state in memory yet: that is W4b.
  - **Network N0:** DOSBox-X's networking is off (no IPX, NE2000 or modem), and the process runs
    under `unshare -n`, as T08 did.
  - **The profile:** `setup/iw-dos/iw-dos-runtime.sh` is idempotent, installs nothing, checks the
    tools, prepares the run directory, and ends by running the `iw-dos` token checks from
    `capabilities.json`. It prints `ready` only if all pass.
  - **The cycle:** `runtime/iw-dos/spike/cycle.py` does launch, known screen, before screenshot,
    one input, after screenshot, terminate and reset.
    - It writes one `run/1` record per run to `runs/E003/`.
    - Bundles go to a local `E003_BUNDLES`, with manifests in `evidence/E003/`, as in E001.
    - Every write goes through the shared confined writer.
  - **F005** (proposed), like F002:

    - one row per probe;
    - "What this does not establish";
    - Artifact `iw-dos-3.1-30121376`, Experiment E003, tier V2. Max intervention: I2 if the
      savestate arm runs, else I0/I1.
  - **Not in scope:**
    - a reusable driver (W5b);
    - any game rule;

  - **Fixed waits without a reason.** Prefer waiting on a pixel condition, as T08 does.

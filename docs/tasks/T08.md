    - Xvfb 21.1.12, xdotool 3.20160805.1, ImageMagick 6.9.12 (`import`, `convert`), and `xwd`.
    - xfwm4 4.18.0, installed by the main session.
    - `unshare -rn` works. `winetricks` and `cabextract` are absent.
  - H3, the generic `preflight`, does not exist yet (game-archaeologist 07 §2: H3 precedes W5a, not
    W3a). The profile therefore ends in its own token checks (Scope, the profile).

- **Scope**:
  - **The paths**:
    - Native Windows: `not tried`, with the owner's direction as the reason. Never start the game
      on the Windows desktop.
    - Wine under Xvfb and xfwm4: try it. The prefix arch follows the PE header: `win32`.
  - **The machine-local places**: these are never committed, and the scripts take them from the
    environment.
    - `IWP_DIR` is the install. It is read only, and only to copy it and hash it.
    - `IWP_PREFIX` is the Wine prefix. It lives outside every checkout and worktree, for example
      `~/.local/share/isle-wars-archaeology/iwp.wineprefix`.
    - The game's copy lives inside the prefix's `C:`. It is copied from `IWP_DIR`, and
      `register_artifact.py check <copy> iwp-2.0-996e86c5` verifies it.
  - **For the Wine path, record each of these with evidence and exact versions**:
    - whether it launches unattended;
    - how to reach a known screen, such as the title screen or the unregistered build's notice;
    - whether one input, key or click, takes effect, shown by before and after screenshots;
    - how to terminate and reset reliably;
    - the files written at runtime: a diff of the game's copy, and of the prefix (files, and
      registry keys by name), before and after;
    - the audio dependency: whether it runs with audio drivers disabled;
    - the display: the Xvfb size and depth that work, and whether the projector changes mode or
      goes full screen;
    - fixed waits: none without recording why; prefer waiting on a window or a pixel condition.
  - **Network N0 for the game**: run the game process under `unshare -rn`, or record why that
    fails and what was used instead. Never open the `.url` shortcuts.
  - **The profile**: `setup/iwp/iwp-runtime.sh` is idempotent.
    - It installs nothing with sudo; it checks the system packages above, and says which is missing.
    - It builds or refreshes the prefix and copies the game into it.
    - It removes `Z:` and the home-folder links.
    - It ends by running every `iwp`-relevant token check from `capabilities.json`. It prints
      `ready` and exits 0 only if all pass, and names each one that fails otherwise.
    - When H3 lands, the ending becomes `preflight --tokens …`; say so in a comment. The tokens
      are those under Runs on.
  - **The cycle**: `runtime/iwp/spike/cycle.py` does launch, then known screen, then a before
    screenshot, one input, an after screenshot, then terminate and reset.
    - Each run writes one `run/1` record to `runs/E001/<run-id>.json`.
    - Screenshots are evidence bundles, with manifests in `evidence/E001/`. The bundles stay in a
      local directory outside the repository, which `E001_BUNDLES` names. The main session uploads
      them to release `E001` after review.
  - **Runtime writes**: if a run changes a file of the set, F002 names it. Register a successor set
    (05 §2) with `register_artifact.py`, with `runtime_writes` filled in.
  - **F002** (proposed), from `formats/templates/finding.md`:
    - Artifact `iwp-2.0-996e86c5`; Experiment E001; tier V2; intervention I0, unless the finding
      says otherwise.
    - One row per path: launch, known screen, input, observe, terminate, reset. Each cell reads
      `works`, `fails: <evidence>` or `not tried: <why>`.
    - A "What this does not establish" section.
  - **Not in scope**: a reusable driver (W5a); any game rule; decompilation; computer vision beyond
    a screenshot hash and a pixel check; Wine tricks generalised into game-archaeologist.

- **Hazards**:
  - **Copying or writing the install.** `IWP_DIR` is read and hashed only. The only copy is the
    one inside the prefix, and nothing from the game enters the worktree, not even temporarily.
  - **A prefix, a game copy, a screenshot or a bundle under the checkout.** All of them live
    outside it.
  - **"It ran once" taken for unattended launch.** Unattended means the cycle runs 3 times with no
    human, from a cold prefix state.
  - **Unrecorded fixed sleeps.** Prefer waiting on a condition.
  - **A stale `wineserver` or Xvfb left running.** Terminate kills both, and the next run checks
    that they are gone.
  - **Machine paths, a user name or the install path in a committed file.** Done-when 8.

# T31 Implementer read access to the machine-local static folder

- **Kind**: harness (a local adaptation of the OpenCode implementer's permissions; no research)
- **Issue**: #89 · **Branch**: `task/T31-implementer-static-access` · **Merge after**: T29 (merged)
- **Implementer**: claude sonnet (`task-agent`, effort `high`), worktree isolation. A Claude agent,
  not an OpenCode model, because the task changes the permissions of the OpenCode implementer
  itself (as T29 did for the reviewer). Sonnet rather than Opus because it follows T29's pattern
  and Claude's weekly pool is low (the owner, 2026-10-05). Sonnet's tripwire applies; escalation:
  Sonnet → Opus.
- **Reviewer**: opencode `gpt-6.1-sol` (GPT-6.1 Sol, effort `low`), another family, after the quota
  check (rule 6). Substitutes: GLM-5.3, then Luna. Lines marked `[C3]` are the main session's.
- **Hard** (rule 6): a guard. Its failure lets an OpenCode implementer write or delete in the static
  folder or reach outside its worktree beyond what is granted, or breaks every implementer run.
- **Why**: The owner decided on 2026-10-05 to let OpenCode implementers (GLM-5.3, DeepSeek) read
  Pro's decompiled Lingo, so the reading tasks (T21, T22, T23, T27, T30, T18) can run on Z.ai or Go
  instead of Claude, whose weekly pool is low. T29 (#82) gave the same read access to the reviewer;
  rule 18 already allows the models' APIs to read derived output.
- **Evidence**:
  - T29: `.opencode/agents/reviewer.md` (the grant `~/.local/share/isle-wars-archaeology/static/*`,
    the shell deny patterns for writes into the static folder), `tests/test_reviewer_permissions.py`,
    `docs/environment.md` (what the patterns cannot stop), and PR #82's findings on OpenCode 1.18.34:
    `~/` is expanded; `*` crosses `/`; the last matching rule wins; the shell checks paths only for
    cd, rm, cp, mv, mkdir, touch, chmod, chown and cat.
  - `.opencode/agents/implementer.md`: `edit: allow` (it must edit its worktree), and
    `external_directory` denies only `/tmp/opencode/*`. A pinned harness copy (`harness.lock`).
  - The T13 lesson (docs/models.md, DeepSeek V4 Pro): an implementer must never write outside its
    worktree; a TMPDIR stays inside it. This task does not grant `/tmp`.
- **Owns**: `.opencode/agents/implementer.md`, `harness.lock` (an `adapt` line, the hash line
  removed), a test file `tests/test_implementer_permissions.py` (sharing helpers with T29's test if
  that is simpler, without weakening it), and the T29 section of `docs/environment.md`.
- **Scope**:
  - **Protects:** the implementer reads, and only reads, one place outside its worktree: the static
    folder. It never writes, deletes or moves anything there, and every other outside path stays
    rejected. No machine path is tracked.
  - **The grant:** allow `~/.local/share/isle-wars-archaeology/static/*` in `external_directory`.
  - **Writes into the static folder:** the edit and write tools are allowed for the worktree; find
    out, from OpenCode 1.18.34's documentation or source (never guess), whether `edit` takes path
    patterns. If it does, deny edits under the static folder. If it does not, say so, and say what
    stops an edit there and what does not. Deny the shell writes into it as T29 does.
  - **The prose:** the agent file's "stay inside your worktree" paragraph names the one read-only
    exception, and says never to copy a line of the decompiled code into the worktree (rule 18).
  - **Not in scope:** `/tmp` or any TMPDIR outside the worktree; the reviewer; the Claude agents.
- **Done when**:
  1. `.opencode/agents/implementer.md` grants the static folder and nothing else new; writes into it
     are denied as far as OpenCode allows, and the PR says what is not stopped.
  2. `[C3]` The main session runs one probe with the implementer agent on a cheap model (GLM-5.3
     Flash), in a scratch worktree, through the code path implement.mjs uses. It must read one `.ls`
     file under the static folder and print its sha256, be refused an `rm` and a `>` write there,
     and be rejected reading a file elsewhere outside its worktree. The PR gives the exact command.
  3. `python3 -m unittest discover -s tests` (TMPDIR outside every checkout) passes, and the new tests
     fail when the grant is removed, when an extra outside path is granted, or when a write deny is
     removed; show the mutants killed. `node tools/harness/review.mjs --self-test` and
     `node tools/harness/implement.mjs --self-test` still pass.
  4. `grep -E '^[0-9a-f]{64}  ' harness.lock | sha256sum -c --quiet` passes, with an `adapt` line for
     the agent file.
  5. `git grep -n -E '/home/|/mnt/' -- .opencode tools/harness harness.lock` prints nothing new.
  6. `python3 tools/check_no_originals.py` and `python3 tools/check_links.py` exit 0; CI is green.

# E007 iw-dos-save-format

Copied from the research task's contract when the experiment was created. After the first run this
file is append-only. A changed design is a new experiment, or `v2/`.

- **Task**: T16 (#64), W4b follow-on
- **Question**: What does each line of DOS *Isle Wars*' `ISLEWAR.SAV` mean, as shown by pairs of runs that differ in one stated action; can a tool write a save from a decoded position, byte for byte as the game does; and does the game load a save the tool wrote and show the written values (set `iw-dos-3.1-30121376`)?
- **Hypotheses**:
  - H0: the lines of the save that F007 left undecoded (the production-centre list, the DFT pair, the other colours' cards, the two constant lines, the last line) do not change in line with any action a run can take, and a crafted save is refused or changed by the game — distinguished by pairs of runs whose save differs in one line, and by the screen and a second Save after loading a crafted save.
  - H1: each of those lines changes in line with an action (the level alone, the starting armies alone, Speed, Sound, a card drawn by a colour, a turn), and the game shows the values of a crafted save — distinguished by the same pairs and by the loaded board.
- **Artifact**: set `iw-dos-3.1-30121376`, variant none (no run changes a file of the set: the game's writes are new files, removed by the reset; a crafted save is placed in the run copy after the launch checks and removed by the reset).
- **Runtime**: `runtime/iw-dos/spike/cycle.py --experiment E007 --steps <script> [--crafted <position>]@<commit in each record>`, the T11 cycle with its seal unchanged, DOSBox-X 2024.03.01, Xvfb, xdotool, ImageMagick, on the user's machine. Maximum intervention level I3: the arms that load a crafted save place a save written by `runtime/iw-dos/save/` in the run copy (I3, a crafted save); every other arm is I1 (screenshots) and reads the game's own files (I0). I3 is the lowest level that sets a position, and only a crafted save can set a chosen one. Each I3 result is corroborated at I0: the same fields in natural saves against the screen, and the game's own second Save after the load, compared byte for byte with the crafted save.
- **Design**:
  - start state: the T11 run copy `S-run-copy-option-box` (the registered files as plain files of the run copy), restored after every run by `rundir.py sync` and checked equal to its start. The game's writes and a crafted save are new files, kept as bundle outputs (`s<NN>-<NAME>` after a `files` step, `end-<NAME>` at the end) and observed (size, sha256).
  - control: the E005 and E007 natural saves; each pair holds every other choice fixed (the board of a start is not controlled: the starts repeat in many runs, F007, and each pair is compared on the lines that do not depend on the board).
  - arms (each differs from the others in one action; the scripts are `steps/<arm>.steps`, generated by `scripts/gen-steps.py`):
    - `sv-<level>-<armies>`: Set level, starting armies, start, Save at the first human turn: Easy 1 (control), Normal 1, Hard 1, Hardest 1, Easy 3, Easy 6, Easy 10, Hard 6 (the level alone at fixed armies; the armies alone at fixed level);
    - `sv-speed-faster`, `sv-speed-slower`, `sv-sound-off`: the control with one setting changed, then Save;
    - `pass-3`, `pass-6-normal`: several human turns of place-all and PASS with no attack, a Save at each turn's start and the CARD button (a colour draws a card on the computers' turns: the cards lines and the stars over turns);
    - `attack-pass`: as `pass-3`, but turn 1 is E005's attack (Blue conquers a country and draws a card);
    - the crafted arms (`load-*`): the option box, the crafted save placed, Load saved game, the board read, Save again, `files`.
  - n per arm: two runs where a single run would be a probe; stopping rule: none, the list is fixed. The first board of a game is not controlled.
- **Measurements**: the bytes of every save and DFT file (file); the owners from the pixels (screen); the armies, the scoreboard's `C>` figures, the hand and the stars read from screenshots by eye (screen); DOSBox-X's exit (process).
- **Outputs**:
  - run records: `runs/E007/`;
  - evidence manifests: `evidence/E007/`, bundles in release `E007` (screenshots, the files the game wrote and the crafted saves, `changes.log`, `run.log`, `dosbox.log`, `dosbox.conf.txt`; never a savestate);
  - exploration before the runs and probe logs: `measurements/` (rule 20);
  - `findings/F009-*.md`, status `proposed`.

## Scripts

- `scripts/cyc.sh ARM STEPS [--explore | --crafted POSITION]`: one run; needs `IW_DOS_DIR`, `IW_DOS_RUN`, `E007_BUNDLES` (and `E007_EXPLORE` with `--explore`) in the environment.
- `scripts/gen-steps.py`: writes the arms' step scripts; `scripts/keep-explore.py KEY...`: copies the text outputs of `--explore` runs into `measurements/explore/`, never replacing or deleting.
- `steps/x*.steps`: the exploration scripts (not records).
